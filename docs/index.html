Living Audit & Build Roadmap

Sama Holidays: build roadmap & progress

A code-level audit of the Sama Holidays booking platform — a boutique Abu Dhabi travel agency — and a staged plan toward a modern, bilingual product that Gulf, Arabic-speaking travellers will trust. This page is regenerated as each item lands.

Last updated 8 Sep 2026 Current focus Stage 0 — pre-launch fixes Working branch feat/stage-0-launch-fixes Stack Next.js 16 · Supabase · Clerk · Stripe · RapidAPI

The platform is architecturally mature: auth, payments, a real supplier integration, an admin CMS, transactional email, rate-limiting and error monitoring are in place and largely working. The gaps are in the things that make this a regional product: genuine Arabic support, local payment methods, conversational help, maps, and the trust signals a UAE agency is expected to show.

Stage 1

A real bilingual product

Not started

Turn "there is a language toggle" into "an Arabic speaker can complete a booking entirely in Arabic, in a correctly mirrored layout, indexed by Google in Arabic." Highest-leverage investment for the target market.

Why this is the priority

The target customer is an Arabic-speaking Gulf traveller. Today the Arabic "translation" covers roughly the home page only; About, Contact, the booking funnel, the account area and all system messages render in English. dir="rtl" is applied by JavaScript after hydration, so first paint is left-to-right and crawlers see an English-only lang="en" page. A half-Arabic checkout signals the agency doesn't really serve that customer.

Appendix

Defects found

Concrete issues in the code, separate from missing features. Struck through once fixed.

  • /request-quote route does not exist but is linked from features/home/PackagesGrid.tsx and app/packages/packages-client.tsx.
  • Placeholder contact data on contact/page.tsx and components/layout/footer.tsx ("123 Travel Street, New York", 1-800 numbers, .travel email); contact-page social links are #.
  • Live secrets in CLAUDE.md — RapidAPI key, Clerk & Stripe webhook secrets committed in plaintext.
  • Documentation drift — CLAUDE.md describes a src/app/[locale]/ tree and named export const proxy; the app is flat-routed and src/proxy.ts uses export default clerkMiddleware(…). Also still references old src/lib/ paths (now src/services|utils|context).
  • next-intl installed but unused; i18n is a bespoke client context with a partial dictionary.
  • <html lang="en"> hardcoded; lang/dir corrected only client-side — RTL flash + wrong language for crawlers.
  • Runtime translation via free public API — translateText() hits api.mymemory.translated.net from the browser.
  • Admin dashboard revenue chart and "Top Destinations" are hardcoded arrays.
  • Home grids ship fictional fallback inventory when Supabase returns nothing.
  • No cookie-consent despite analytics loading and a privacy policy implying choice.
  • Wholesale "use client" on about, contact, packages-client, hotel-detail-client and others.
  • Playwright dependency with no tests and no CI wiring.
